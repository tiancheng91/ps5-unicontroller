# 配置与日志

配置文件 /data/unicontroller/settings.json，schema_version=1。字段 recording_level/page_level（off/error/warn/info/debug/trace）、rumble（bool）、swap_ab（bool）、button_mapping（32个0..31的整数）。另有 bluetooth_auto_start（bool，默认true）、bluetooth_auto_trigger（login/resume，默认login）、bluetooth_auto_user（上次手动成功启动蓝牙的账号，默认0，仅服务端更新）。旧配置缺少新增字段时按默认值读取；已显式保存的自动启动开关不被默认值覆盖。默认Info、允许震动、无翻转、identity映射。震动只是偏好值；手机后端没有物理马达。

设置分区 `/#settings`；旧 `/settings` 入口兼容。读写通过 /api/v1/settings；所有设置均可在连接期间保存；全局按键映射和模拟手柄布局从下一份输入报文生效，不重建手柄、不改变账号关系。先校验、写入成功后才应用，保存失败不修改运行偏好。日志 /api/v1/logs?level=info；页面阈值不能恢复后台未记录日志。

持久化采用JSON和同目录0600临时文件、fsync与rename；损坏或未来版本拒绝启动，不覆盖原文件。当前通过进程实例锁保持单实例；尚无目录fsync与并发更新版本校验。记录这些限制而不声称跨进程事务保证。

蓝牙配对密钥独立保存于 bonds.db，不放入JSON偏好配置或普通日志/API响应。自动启动规则见 [蓝牙说明](bluetooth.md)。

翻转 ABXY 按键为标准Cross14↔Circle13与Square15↔Triangle12两组交换，之后单次映射，多源按OR。页面明确显示两组面键交换，避免按厂商印字误判。

为兼容已有 JSON，字段名仍为 `swap_ab`，但其含义现在是完整面键布局切换（A/B 和 X/Y 同时交换）。旧配置为 true 时升级后也会交换 X/Y；默认 false。此字段现在只作用于模拟手柄；实体手柄的独立选项见下文。

网页外观（语言、主题）与此文件分离，保存在当前浏览器localStorage `unicontroller.appearance.v1`。首次按浏览器语言选择中文/英文；存储不可用时回退默认，不影响后端配置及蓝牙配对。外观区立即应用，不需要先停止输入源；后端按键布局设置也可在连接期间保存。尺寸和方向导航不再提供设置项：UA 匹配 `PlayStation 5` 时自动启用电视大字体与方向导航，其他浏览器保持普通布局、原生键盘与触摸操作。旧 localStorage 中的 size/navigation 被忽略并在下次保存外观时移除；UA 仅影响页面体验，不参与 API 权限或设备识别。

## 诊断导出

管理页核心事件显示为逐行文本，例如 `[mono 93082.281s] [ERROR] core create_failed generation=1 session=569`。mono 是单调时钟秒数，不能当作日历时间。覆盖计数独立显示；HTTP `/logs` 保留结构化 JSON，方便工具处理。

复制与导出同时收集系统、蓝牙、USB、测试输出的即时状态，以及 `/diagnostics` 返回的 runtime.log 最后32 KiB。核心事件遵循页面日志级别与暂停状态；底层日志和核心事件保留各自来源，不伪造统一时间顺序。某一诊断接口不可用时保留其它部分并写明错误，不把缺失日志解释为硬件正常。

蓝牙虚拟输出创建失败后停止整个蓝牙服务，关闭共享 HCI，再继续必要的虚拟设备清理；不会因下一帧输入自动重新创建。此时所有桥接蓝牙手柄均断开，需手动启用。该保护不能证明共享 HCI 与原装手柄共存安全。

USB运行日志记录 ugen 枚举、VID/PID、描述符筛选和接口打开失败阶段；使用有界、限次输出避免轮询刷屏。不强制解除系统驱动占用，不执行设备重置。

## 日志实现

运行日志使用固定提交的 `rxi/log.c`（MIT），源码随仓库离线编译，来源与校验值见 `vendor/rxi-log/README.md`。上游文件不修改；`src/logging.c` 只适配现有设置级别、单行输出及文件轮转。`src/drivers/common/log.h` 是旧驱动入口的兼容头，不再包含另一套日志实现。

应用代码使用 `uc_log_error/warn/info/debug/trace`，不能直接使用 rxi 的 `log_set_level`：项目仍是 Off=0、Error=1、Warn=2、Info=3、Debug=4、Trace=5，而上游枚举方向不同。`uc_log_set_level` 统一转换；默认 Info。旧驱动的 `log_line` 按 Info 处理，具体错误点可改为相应的 `uc_log_*`。当前是单事件循环，同步输出并刷新，不引入额外日志线程。

`runtime.log` 采用日历时间、级别、源码位置及消息的一行格式；时间使用运行环境的本地时间设置，秒级精度。核心事件消息额外保留 `mono_ms`、generation 和 session，便于与输入时序关联。格式示例：

```text
2026-11-13 18:15:32 ERROR src/ps5/backend.c:104 bind failed rc=0x...
```

消息最多2047字节，超长标记 `[truncated]`；换行、回车和制表符转换为空格，避免设备元信息伪造多行记录。达到1 MiB后，在后续可记录消息到来时轮转为 `runtime.log.1`，最多保留当前文件与上一份；单条记录可使文件暂时超过阈值。轮转失败继续写现有句柄，不递归记录故障。关闭文件后回退 stderr；生产入口仍重定向 stderr 以承接第三方直接输出。

核心环形事件继续供 `/api/v1/logs` 使用，并同时进入统一运行日志。因此完整导出中的核心片段与 runtime.log 可能包含同一事件；两者分别是过滤快照和文件尾部，不是两个独立的输入事件。页面级别只过滤核心页面快照，不改变已经写入的文件。生产环境仍需 Actions 交叉构建和实机验证，不以主机轮转测试代表 PS5 文件系统表现。

## 每个实体手柄的选项

连接后打开“设备详情”，可独立设置“允许震动”和“翻转 ABXY 按键”，保存后立即生效，不必停止其他手柄。翻转同时交换 Cross↔Circle、Square↔Triangle，在全局自定义映射之前只执行一次。原设置页的 `swap_ab` 现在只控制模拟手柄；不会自动复制到实体设备，实体设备首次默认不翻转。

震动默认策略：设备表中已知的型号或专用协议身份默认开启；未匹配设备表的设备默认关闭并标注“试验性”，即使描述符可识别为 XInput 也不自动开启。显式保存的选择优先于默认值。震动偏好与实际驱动能力独立：Generic HID 目前没有震动输出，打开选项也不会猜测或发送厂商报文。设置页的 `rumble` 仍是总开关；总开关关闭时，所有实体手柄禁止震动。单设备开关同时控制游戏震动与蓝牙连接提示震动；关闭时立即停止该设备马达，重新开启不会补发已经过期的连接提示。

偏好保存在 `/data/unicontroller/device-settings.json`，与配对密钥、协议设备表分离，最多保存64条。沿用受限 JSON、0600临时文件、fsync和rename；写入成功后才修改运行状态，损坏文件拒绝启动且不覆盖。每次连接与修改均记录 key、已知标志和选项，不记录配对密钥。

```json
{
  "schema_version": 1,
  "devices": [
    {
      "key": "classic:E0:10:1D:65:BC:02:057E:2009",
      "rumble": true,
      "swap_ab": false
    },
    {
      "key": "usb:/dev/ugen1.2:3537:1041",
      "rumble": false,
      "swap_ab": true
    }
  ]
}
```

蓝牙 key 包含 Classic/BLE、地址及 VID/PID；同型号不同地址互不影响，不合并疑似同源的两个地址。USB 当前没有读取可靠序列号，使用节点和 VID/PID 区分：同型号处于不同节点时可独立配置；节点重新编号或更换端口后可能使用默认值，同型号设备复用相同节点也会继承该节点的偏好。因此 USB 偏好是“节点与型号”的配置，不是对物理个体永久身份的保证。

`POST /api/v1/device-settings` 要求现有同源认证，完整提交 `key`、`session_id`、`rumble`、`swap_ab`。服务端必须匹配当前已连接设备和会话后才保存，已断开或被替换的设备返回409。蓝牙和USB状态接口返回 `settings_key`、`known_device`、`rumble`、`swap_ab`，供页面展示；`rumble_available` 表示当前驱动输出是否可用，不能代替用户偏好。此接口不创建虚拟设备、不变更账号绑定，也不启动传输。

## USB 与蓝牙自动启动

自动启动区提供两个独立开关：`bluetooth_auto_start`（默认true）和 `usb_auto_start`（默认false）。共用启动时机 `bluetooth_auto_trigger`：`login` 为登录进入桌面后，`resume` 为休眠恢复实验。保留原字段名以兼容旧配置；旧文件缺少 USB 字段时按关闭处理。两种时机均使用蓝牙15秒、USB25秒延迟与120秒观察窗口，不另建竞争的系统日志读取器。

USB 的 `usb_auto_user` 默认0，仅在手动 USB 启动成功后由服务器保存；HTTP 设置不能覆盖该账号。自动启动要求该账号已登录且平台允许启动，不自行换绑其他账号。未记住账号时，先手动启用一次 USB。休眠恢复期间未登录时继续等待；观察窗口内仍不满足条件则不启动，需手动启用。USB 不参与未登录的虚拟手柄实验。

登录桌面模式可同时启用蓝牙与USB：同一平台事件后，蓝牙15秒、USB25秒分别启动符合条件的服务。USB在共享15秒观察门槛后再排队10秒；手动操作、休眠、账号不可用或自动启动设置改变会取消排队。不同实体手柄仍使用独立会话；多人游戏仍需不同账号，不承诺同时打开服务就会自动分配不同玩家。自动启动只开启连接/枚举服务，不自动开始配对。

休眠恢复模式下，现有蓝牙实验输出需要独占，因此不能同时启用两种自动启动。页面阻止保存冲突组合，服务器也拒绝；USB单独恢复时仍要求已记住且已登录的账号。手动启动/停止任一服务会取消本轮自动启动；下次休眠后按保存的策略重新观察。失败不自动重试，不能取代实机恢复及原装手柄共存验证。

## 模拟手柄用途

模拟手柄用于从手机或电脑验证虚拟输出链路、PS键、账号选择与游戏内输入，帮助将平台输出问题和实体手柄传输/协议问题分开排查。启用前必须停止本程序的蓝牙与USB服务，测试后先停用模拟手柄再恢复实体输入。

该互斥是当前项目为测试隔离采取的策略，不是PS5硬件要求：HTTP路由、页面和核心会话均实施了这一限制。实体蓝牙与USB已经支持不同账号下的多会话，但模拟手柄仍使用独占测试路径。若未来需要同时使用，需将测试端纳入多源会话管理并验证账号冲突、停止与休眠清理；本次只补充说明，保留已验证的隔离行为。

自动启动选项在线保存时不打开观察器、不重启现有服务，新策略在下次休眠周期后生效；未运行输入源时仍可等待新的桌面事件。只修改日志、震动等无关选项不会重置现有自动启动计时。保存设置不会自动停用任何手柄；需停用后修改布局时，页面给出明确提示。

## 手柄震动测试

设备详情中的“测试震动（0.5秒）”只针对当前手柄，需同时开启全局和单设备震动。没有实现输出、初始化未完成、输出已失败或设备断开时不可测试；Generic HID 目前只有输入实现，开关开启不代表支持震动。

认证接口 `POST /api/v1/rumble-test` 接受 `key` 和 `session_id`，在现有连接中校验身份后才接受请求，不注册虚拟设备、不改绑账号。成功返回202及 `{queued:true,duration_ms:500}`，表示已接受测试，不是设备实际震动的确认。请求过频返回429；连接已变化、选项关闭或无可用输出返回409。

蓝牙复用已有的短震动定时器；USB复用标准XInput马达输出，测试期间覆盖游戏马达值，500ms到期先发停止，再恢复正常反馈轮询。每设备每秒最多接受一次；断线、关闭震动或停用服务会取消测试。仅使用已有协议输出，不猜测厂商命令。日志记录设备身份、时长及驱动接受状态；USB写失败仍保留输入并禁用该连接输出。实际效果必须通过实机确认。
