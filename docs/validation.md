# 验证说明

当前已通过：C11严格编译、核心/平台/协议/输入源管理单测、HTTP/UI回归、格式检查、PS5 SDK交叉编译及Actions完整ELF链接。USB与分层调整代码0f0db10的[构建记录](https://github.com/tiancheng91/ps5-unicontroller/actions/runs/42821929782)。

未完成：PS5实机USB接口、实体手柄输入/回连/热插拔、原装DualSense共存与重复待机。不能据此声称已在PS5游戏中可用；完整ELF由Actions构建，不要求本地Docker。

HTTP集成覆盖鉴权、Origin、超限请求、设置保存与失败保留、手柄启停、旧序号拒绝、慢请求不阻塞服务。500ms释放及清理失败重试由核心测试验证。

## 实机步骤

1. 保持原装DualSense正常，通过payload loader载入 unicontroller.elf。
2. 手机与PS5同网，通过 http://PS5-IP:7456/ 访问；控制器默认关闭。
3. 打开 /controller，选择独立已登录账号，显式启用，等待识别完成。
4. 测试方向、面键、摇杆、PS与Options；进入同账号启动的原生游戏验证。
5. 按住操作后切后台/断网，确认500ms左右释放，不持续按住。
6. 停用，再次启用；原装手柄应持续正常。待机恢复后重新启用。
7. 导出 /api/v1/logs，并保存版本、账号、错误与发生步骤。

不要把 host mock 二进制重命名为 ELF。实际PS5构建由GitHub Actions产出 unicontroller.elf 和 SHA256。

默认监听 7456；绑定失败时仅再尝试 7457。两者均失败则启动失败，日志记录失败原因及实际监听端口。页面使用相对 URL，备用端口同样可用。

## 本次实机前补齐

- 进程实例锁在提权/SDK初始化前获取，避免重复加载两个服务。
- 启动、平台识别及错误记录在 /data/unicontroller/runtime.log，启动时超过1MiB保留上一份；网页 /api/v1/diagnostics 返回最后32KiB。
- 控制面可停止payload；鉴权后返回成功响应，再清理并退出。
- 修复账号退出清理、设备识别歧义等待、重复启用和取消竞争；页面支持没有 AbortSignal.timeout 的浏览器。
- 所有页面导航指向服务器实际路由；新增UI行为测试。

实机先验证虚拟手柄；蓝牙默认关闭，按[蓝牙接入](bluetooth.md)单独开启并验证。若7456被占用访问7457。先登录两个账号，再在手机页选择独立账号；若没有账号列表先导出平台日志，不反复盲试创建。

## 休眠与账号保护

休眠进入时释放并删除本实例虚拟设备；删除失败保留句柄并重试。恢复后默认关闭，不自动注册。网页手动启用还必须满足电源状态明确为工作且持续5秒、所选账号仍已登录。电源未知或休眠时拒绝创建；等待窗口返回pending但不调用AddDevice。不是旧版桌面焦点自动恢复策略。

触控页包含PS键（bit16 / 0x00010000），与其它按键共用心跳和超时释放；创建时还显式绑定所选账号。请为第二手柄选择独立账号。

## 蓝牙主机验证

新增协议栈模拟测试覆盖Classic/BLE连接、丢包、描述符、Switch Pro BLE拒绝、USB传输工具与配对加密；输入源管理测试覆盖首帧建会话、慢识别不重放过期按键、源互斥、断线清理和删除失败仍关闭HCI。HTTP与页面测试覆盖鉴权、启停、限时配对、忘记设备、失败反馈及防重复启动。SDK头文件交叉语法检查通过。

这些测试不证明共享HCI共存、真实配对回连或游戏输入；蓝牙及本次USB接入的完整ELF已由Actions链接通过。只在输入变化时上报的设备可能被500ms释放策略提前释放，需按型号验证。

## USB接入与目录分层

新增USB协议/描述符、USB源管理与UI测试，覆盖保护设备拒绝、GIP/无线协议拒绝、ACK重试/超时、错误报文、端点布局、慢绑定不重放、长按与拔线、清理失败仍释放接口、三源互斥。共享协议和工具迁移后仍需运行完整蓝牙回归。USB_FS真实收发、接口占用ioctl、热插拔及待机需PS5实机验证；SDK编译通过不能替代这些步骤。
