# 验证说明

当前已通过：C11严格编译、核心/平台/协议/输入源管理单测、HTTP/UI回归、格式检查、PS5 SDK交叉编译及Actions完整ELF链接。USB与分层调整代码0f0db10的[构建记录](https://github.com/tiancheng91/ps5-unicontroller/actions/runs/42821929782)。

未完成：PS5实机USB接口、实体手柄输入/回连/热插拔、原装DualSense共存与重复待机。不能据此声称已在PS5游戏中可用；完整ELF由Actions构建，不要求本地Docker。

HTTP集成覆盖鉴权、Origin、超限请求、设置保存与失败保留、手柄启停、旧序号拒绝、慢请求不阻塞服务。500ms释放及清理失败重试由核心测试验证。

## 实机步骤

1. 保持原装DualSense正常，通过payload loader载入 unicontroller.elf。
2. 手机与PS5同网，通过 http://PS5-IP:7456/ 访问；控制器默认关闭。
3. 打开 /controller，选择独立已登录账号，显式启用，等待识别完成。
4. 测试方向、面键、摇杆、PS与Options；进入同账号启动的原生游戏验证。
5. 按住操作后切后台/断网，确认500ms左右释放，不持续按住。
6. 停用，再次启用；原装手柄应持续正常。待机恢复后重新启用。
7. 使用管理页“导出”获取完整诊断（核心事件、状态快照、底层运行日志），并保存版本、账号、错误与发生步骤。单独 /api/v1/logs 不包含蓝牙/USB底层日志。

不要把 host mock 二进制重命名为 ELF。实际PS5构建由GitHub Actions产出 unicontroller.elf 和 SHA256。

固定监听7456；启动时 socket、绑定或监听失败立即退出，不再回退7457。休眠不主动关闭监听；SIGCONT或事件循环长间隔后检查并重新确认监听。运行期失败记录阶段和errno，每秒最多重建一次，连续10次恢复仍未成功接受请求则退出。恢复网络不会启动蓝牙或USB。

## 本次实机前补齐

- 进程实例锁在提权/SDK初始化前获取，避免重复加载两个服务。
- 启动、平台识别及错误记录在 /data/unicontroller/runtime.log，启动时超过1MiB保留上一份；网页 /api/v1/diagnostics 返回最后32KiB。
- 控制面可停止payload；鉴权后返回成功响应，再清理并退出。
- 修复账号退出清理、设备识别歧义等待、重复启用和取消竞争；页面支持没有 AbortSignal.timeout 的浏览器。
- 所有页面导航指向服务器实际路由；新增UI行为测试。

实机先验证虚拟手柄；USB自动启动默认关闭，蓝牙按[蓝牙接入](bluetooth.md)单独开启并验证。若7456被占用，程序启动失败，需先排除端口冲突。先登录两个账号，再在手机页选择独立账号；若没有账号列表先导出平台日志，不反复盲试创建。

## 休眠与账号保护

休眠进入时释放并删除本实例虚拟设备；删除失败保留句柄并重试。恢复后按照保存的自动启动选项处理，手动模式不自动注册。网页手动启用还必须满足电源状态明确为工作且持续5秒、所选账号仍已登录。电源未知或休眠时拒绝创建；等待窗口返回pending但不调用AddDevice。可选桌面自动启动和实验性休眠恢复模式另见[本次实机清单](test-checklist.md)。实验模式允许未登录注入，但不宣称已完成系统账号绑定。

触控页包含PS键（bit16 / 0x00010000），与其它按键共用心跳和超时释放；创建时还显式绑定所选账号。请为第二手柄选择独立账号。

## 蓝牙主机验证

新增协议栈模拟测试覆盖Classic/BLE连接、丢包、描述符、Switch Pro BLE拒绝、USB传输工具与配对加密；输入源管理测试覆盖首帧建会话、慢识别不重放过期按键、源互斥、断线清理和删除失败仍关闭HCI。HTTP与页面测试覆盖鉴权、启停、限时配对、忘记设备、失败反馈及防重复启动。SDK头文件交叉语法检查通过。

这些测试不证明共享HCI共存、真实配对回连或游戏输入；蓝牙及本次USB接入的完整ELF已由Actions链接通过。只在输入变化时上报的设备可能被500ms释放策略提前释放，需按型号验证。

## USB接入与目录分层

新增USB协议/描述符、USB源管理与UI测试，覆盖保护设备拒绝、GIP/无线协议拒绝、ACK重试/超时、错误报文、端点布局、慢绑定不重放、长按与拔线、清理失败仍释放接口、三源互斥。共享协议和工具迁移后仍需运行完整蓝牙回归。USB_FS真实收发、接口占用ioctl、热插拔及待机需PS5实机验证；SDK编译通过不能替代这些步骤。

## 多实体输入与游戏震动验收

- 首台手柄使用启动时选择的账号。第二台连接后，在控制面上方选择另一个已登录账号，再点击对应设备卡片的“绑定到上方所选账号”。未分配账号的设备可以显示输入帧，但不向PS5注入输入。
- 测试两台蓝牙、两台USB，以及蓝牙和USB混合；确认各自账号、PS键、摇杆和游戏操作独立。总计最多四个虚拟输出，原装手柄仍使用系统自己的路径。
- 在支持本地双人的游戏中分别触发震动，检查只震动对应实体手柄；持续震动、强弱马达、归零停止及全局震动关闭都需要测试。原项目已验证的Switch反馈路径不等于本项目整条链路已经实测。
- 保持一台长按时断开另一台、取消待注册设备、切换其中一台账号，确认未误删另一输出。重新绑定后只接受新输入，不重放旧按键。
- 待机前应删除全部自有输出并关闭传输；恢复后保持关闭，原装手柄可单独操作，再手动启动。
- API：POST `/api/v1/bluetooth/assign` 使用 `{ "slot": 0, "address": "AA:BB:CC:DD:EE:FF", "user_id": 1 }`；POST `/api/v1/usb/assign` 使用 `{ "slot": 0, "node": "/dev/ugen0.1", "user_id": 2 }`。槽位和设备标识必须同时匹配，失败不改变其他设备。

## 休眠恢复网络验证

- 冷启动确认7456监听；端口被占用时确认新进程退出且原监听不受影响。
- 默认手动模式进入休眠再恢复：进程保持，控制页和诊断接口恢复可访问，蓝牙/USB仍关闭。
- 登录触发模式：恢复后等待主手柄完成登录并进入桌面，蓝牙等待15秒、USB等待25秒后启动。
- 休眠恢复触发模式：系统恢复后蓝牙等待15秒、USB等待25秒后启动配置允许的输入服务，沿用现有账号/连接方式限制。
- 重复休眠至少3轮；原装手柄始终正常。日志检查`[lifecycle]`、`[http]`和`[input-auto]`，不得只看Payload Manager进程状态。
- 主机故障注入覆盖启动绑定失败、SIGCONT、监听描述符失效、重建成功和连续重建失败退出；不能替代PS5实机验证。

桌面自动启动观察期间，诊断日志捕获最多256 KiB，达到上限后继续读取并解析事件；120秒观察超时保持不变，自动启动延迟为蓝牙15秒、USB25秒。正常休眠的蓝牙/USB状态为off，不再显示失败；真正的日志读取或写入失败仍取消自动启动并记录原因。
