# 蓝牙输入接入（实机待验证）

## 范围

默认关闭，支持网页手动启动及可选的桌面事件自动启动。启动时选择首台手柄的已登录PS5账号；每个实体输入源占用独立虚拟输出，额外手柄在设备卡片绑定其他已登录账号。网页测试手柄与蓝牙互斥，不把两个来源混到同一会话。默认重启/休眠后不自动打开HCI；启用自动启动后的条件见下文。手动启动仍要求明确工作状态持续5秒、所选账号已登录。

当前接入Classic HID与BLE HID。已知Switch Pro与Joy-Con L/R走专用配置，已知Xbox蓝牙型号走Xbox配置；未知型号必须通过可用HID描述符解析，不把所有非Switch设备强制按Xbox格式读取。Switch2、Joy-Con合并、厂商私有蓝牙协议、Xbox专用无线接收器不在支持范围。

第三方Switch Pro兼容模式若使用057e:2009，BLE入口被拒绝并不保存新的BLE配对，使用Classic入口。不同蓝牙地址不凭相似性合并；同VID/PID不等于同设备。其他已知Nintendo BLE身份仍需要实机验证。

## 流程

1. 保持原装手柄可用，登录两个账号。
2. 控制面选独立账号，关闭网页测试输出，再点启动蓝牙。
3. 点击配对60秒，把实体手柄放入其蓝牙配对模式。
4. 页面分别显示连接、输入帧、电量和是否绑定。连接成功不等于输入有效。
5. 实体连接成功1秒后，支持震动的手柄短震动200ms，每次连接仅提示一次；受设置里的震动开关控制。协议初始化未完成时最多等到连接后5秒，断线/停止/休眠取消提示，不阻塞输入。
6. 首个有效输入后才创建虚拟设备；初始化期间不会重放过期的按键。
7. 使用相同独立账号进入游戏，测试PS键、方向、面键和双摇杆。
8. 通过忘记设备删除本应用配对记录；休眠后默认需手动启动；开启桌面自动启动时先等待新的桌面事件，已保存设备再尝试回连。

首个有效输入源使用启动时所选账号，额外设备保持连接待分配账号。蓝牙与USB合计最多四个输出，同一账号不会分配给两台实体手柄。当前输入静默500ms释放按键，这是偏向安全的策略；只在状态变化时上报的设备可能需要专门的保活/租约适配，不能仅凭通用HID识别成功就声称所有型号已可用。游戏震动从各虚拟设备独立读取，按会话转发到对应实体槽位；旧反馈超过500ms停止。读取失败只禁用对应设备的反馈，不阻断输入。

## 生命周期与安全边界

HCI使用旧项目的受限访问实现，不reset或detach系统驱动，不提高线程优先级。第一HCI功能与系统功能是否完全隔离尚未证明。仅在手动启动或自动启动门槛满足后打开；首次实机仍须确认原装DualSense共存正常，不能把模拟测试当成共存验证。

停止/休眠先尝试释放/删除自有虚拟输出，同时保证即使删除失败也关闭共享蓝牙传输；保留句柄继续清理。初始化等待期间持续观察电源。配对任务有期限，连接、通道、报文重组均有上限。不开放自动切换到其他HCI接口。

## 存储与日志

本应用独立 /data/unicontroller/bonds.db，格式继承迁移的host栈；临时文件权限0600、fsync后原子替换。与settings.json隔离，不读取/清理PS5系统配对记录。原项目的配对文件不会自动迁移。

保留驱动匹配、初始化、收包/解析计数、状态、错误原因等元信息；不记录配对密钥或原始HCI/ACL载荷。移植栈的兼容日志统一归Info，受后台记录阈值控制。结构化core日志与平台runtime.log仍可从网页导出。

## 验证

make test-bluetooth、test-bt-manager、test-bt-ui、test-web，随后Actions实际链接ELF。主机默认不具备PS5 HCI：启动返回明确失败，不模拟成功连接。实体手柄兼容矩阵必须在PS5实机后补充。

## BLE 接入策略

BLE 默认拒绝，只有内置设备记录明确 `ble: true` 或用户覆盖规则明确开放的身份可以接入。当前内置仅开放 Xbox `045e:0b13`，依据为端到端模拟测试，PS5 实机支持仍待验证。设备名称、Classic profile、USB ID 或 HID 布局本身不授予 BLE 权限。Switch 家族身份继续拒绝，即使用户配置 `ble: true` 也不绕过。

用户覆盖文件 `/data/unicontroller/controllers.json` 的设备规则可使用 `match: {transport: "ble", vid: "1234", pid: "5678"}` 和 `ble: true`。`ble: false` 可关闭内置已开放身份；字段仅允许用于 BLE 规则。通用 HID 仍可用于显式开放的未知设备。

首次需要连接读取 PnP ID。当前栈仍先完成加密握手再查询 GATT，未改为配对前查询；身份未通过前不保存新密钥或发布手柄就绪事件。缺少/读取失败的身份拒绝。已有配对在发起回连前也检查权限，记录保留供用户查看与删除，不自动删除历史数据。拒绝身份暂缓再次尝试 60 秒。输入通知订阅失败或没有可订阅输入报告时退出初始化。

## 可选自动启动

设置页保留 `bluetooth_auto_start` 布尔开关（默认 false），新增 `bluetooth_auto_trigger`：`login`（默认，登录进入桌面）或 `resume`（实验，休眠恢复）。旧配置没有 trigger 时按 login 读取。两种策略均等待连续稳定 5 秒、所有输入源停止和旧虚拟输出清理完成；每轮仅尝试一次，失败不自动重试，不自动开启配对，不实现第三方手柄唤醒。

### 登录进入桌面（推荐）

payload 启动、保存设置或休眠清理后，等待系统工作，再观察最多 120 秒。先排空日志历史，等待新的 SceShellUI 桌面焦点事件（`Render.NPXS40002`），确认前台用户和已保存的绑定账号已登录，连续稳定 5 秒后启动蓝牙。离开桌面或条件失效会取消计时。

桌面焦点来自现有日志流，不是官方物理手柄登录回调，不能证明登录来自哪只手柄。复用虚拟设备识别的日志读取器，读取有界；识别和观察不会同时争抢 `/dev/klog`。日志不可用、断开、观察超时均保持关闭，允许手动启动。在桌面已稳定时加载 payload 不会拿旧事件补触发，需要新的桌面焦点事件或手动启动。

### 休眠恢复（实验）

只在运行中检测到休眠/恢复周期后触发，加载 payload 或保存设置不触发。沿用平台的保守休眠检测：明确休眠电源状态或超过 2 秒的事件循环中断都会请求清理，长中断也可能触发该策略。系统恢复工作并连续稳定 5 秒后启动蓝牙，不要求有已登录用户，也不依赖桌面日志。恢复后最多等待 120 秒；被其他输入源持续占用时不抢占。

首台收到新有效输入的实体手柄创建未由应用绑定的虚拟设备，允许未登录时注入 PS/Home、方向和确认等按键。该路径跳过 `sceMbusBindDeviceWithUserId`，保留同一虚拟设备继续注入，让系统用户选择流程决定账号归属。保存的账号不用于这个模式，网页主动账号分配禁用。仅允许一只实验输入源，核心与平台都阻止它和其他应用虚拟输出混用。

此路径目的是实测“第三方手柄操作用户选择并进入游戏”，不保证系统会完成绑定。尚无可靠的设备归属查询接口，页面单独标注输出是否已启用，以及“系统绑定未确认”；不把已登录用户或前台账号作为该设备归属。日志记录虚拟设备创建、首次输入/PS键注入结果和用户列表变化；输入提交成功也不能证明游戏已经接收。

账号登录/退出不会触发应用重绑或重建设备，便于测试系统自身的用户切换。原有输入超时释放、断线清理、停止及休眠删除仍生效。提前访问 HCI 和未绑定虚拟设备是否影响原装手柄恢复尚待实机验证，因此保留实验标记和默认关闭。测试步骤见[实机清单](test-checklist.md)。

### 账号与取消规则

保存上次**手动成功启动蓝牙**的账号到 settings.json 的 `bluetooth_auto_user`；默认 0 表示无记录。前台用户与绑定账号可以不同，不把第三方手柄自动改绑主手柄账号。设备卡片分配用于当前会话，额外实体手柄仍单独分配，不宣称已持久化每台手柄的账号。

手动启动/停止取消本轮自动任务。休眠清理取消旧计时与日志状态，恢复后按所选策略重新等待。USB 不自动恢复，不自动设置系统辅助控制器模式。
