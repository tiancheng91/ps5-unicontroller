# 蓝牙输入接入（实机待验证）

## 范围

默认关闭，支持网页手动启动及可选的桌面事件自动启动。首台手柄默认推荐已登录初始用户，其次前台用户、首个已登录用户，每个实体输入源占用独立虚拟输出。设备详情可请求 PS5 重新选择使用者，页面不推断最终账号归属。网页测试手柄与蓝牙互斥，不把两个来源混到同一会话。默认重启/休眠后不自动打开HCI；启用自动启动后的条件见下文。手动启动仍要求明确工作状态持续5秒、所选账号已登录。

当前接入Classic HID与BLE HID。已知Switch Pro与Joy-Con L/R走专用配置，已知Xbox蓝牙型号走Xbox配置；未知型号必须通过可用HID描述符解析，不把所有非Switch设备强制按Xbox格式读取。Switch 2 系列 BLE 当前仅识别广播型号，标记不支持并禁止配对。Joy-Con合并、其它厂商私有蓝牙协议、Xbox专用无线接收器不在支持范围。

第三方Switch Pro兼容模式若使用057e:2009，BLE入口被拒绝并不保存新的BLE配对，使用Classic入口。不同蓝牙地址不凭相似性合并；同VID/PID不等于同设备。Switch 2 BLE 不进入连接、SMP 或 GATT 初始化。

## 流程

1. 保持原装手柄可用，登录两个账号。
2. 关闭网页测试输出，在设置启用蓝牙；默认按推荐的已登录账号准备输出，需要重新选择使用者时使用设备详情按钮，由 PS5 完成选择；每次只重建选中的设备。
3. 点击“新增蓝牙设备”，让手柄进入配对模式后开始搜索。扫描只显示发现结果，用户点选某个设备的“配对”才建立连接；Switch模式选择Classic。
4. 页面分别显示连接、输入帧、电量和虚拟输出状态。连接成功不等于输入有效。
5. 实体连接成功1秒后，支持震动的手柄短震动200ms，每次连接仅提示一次；受设置里的震动开关控制。协议初始化未完成时最多等到连接后5秒，断线/停止/休眠取消提示，不阻塞输入。
6. 首个有效输入后才创建虚拟设备；初始化期间不会重放过期的按键。
7. 使用相同独立账号进入游戏，测试PS键、方向、面键和双摇杆。
8. 通过忘记设备删除本应用配对记录；休眠后默认需手动启动；开启桌面自动启动时先等待新的桌面事件，已保存设备再尝试回连。

首个有效输入源使用启动时所选账号，额外设备保持连接待分配账号。蓝牙与USB合计最多四个输出，同一账号不会分配给两台实体手柄。当前输入静默500ms释放按键，这是偏向安全的策略；只在状态变化时上报的设备可能需要专门的保活/租约适配，不能仅凭通用HID识别成功就声称所有型号已可用。游戏震动从各虚拟设备独立读取，按会话转发到对应实体槽位；旧反馈超过500ms停止。读取失败只禁用对应设备的反馈，不阻断输入。

## 蓝牙识别顺序

蓝牙认证先于协议选择，不依据 Switch/Xbox profile 决定配对密钥或安全算法。下面是 Classic 的实际顺序，代码入口为 `host.c:link_step` 和 `profiles.c:profile_classic_candidate`。

| 顺序 | 判断                                      | 结果                                                                                                                           |
| ---- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 1    | 已知原装 PS5 身份／系统持有设备           | 保留给系统；取得 SDP 身份后再次检查，配置不能绕过                                                                              |
| 2    | 用户点选配对，或已有配对设备回连          | 完成 Classic 认证和加密；失败不进入协议查询                                                                                    |
| 3    | 配对记录或 SDP 的 VID/PID；必要时查询名称 | 缺失名称且配置可能按名称匹配时，已知 VID/PID 也执行最多 2 秒的名称查询                                                         |
| 4    | 用户配置的精确规则                        | 地址优先于名称，名称优先于仅 VID/PID；多个条件全部匹配，选中的整条规则生效，不跨规则合并字段                                   |
| 5    | 零 VID/PID                                | 按 SDL 的三个精确名称筛选 Switch 候选：`Lic Pro Controller`、`Nintendo Wireless Gamepad`、`Wireless Gamepad`；其他名称不盲探测 |
| 6    | `0001:0001` 占位身份                      | 按标准手柄候选处理，读取 HID 描述符，不推测为 Xbox/Switch                                                                      |
| 7    | 其余内置 VID/PID                          | 选择已知 Switch、Joy-Con、Sony、Xbox 等 profile；名称不能覆盖非零的已知身份                                                    |
| 8    | SDL VID/PID 家族                          | 本地表未匹配时选择已有 Classic 解析器候选；未实现的专用协议标记不支持并断开                                                    |
| 9    | 同地址配对记录中已验证的 Switch 类型提示  | 仅在前面没有选出协议且没有显式 profile 覆盖时使用；仍重新验证                                                                  |
| 10   | 没有专用协议                              | 读取 HID 报告描述符，按通用 HID 解析；不把所有未知设备当成 Switch/Xbox                                                         |
| 11   | Switch 候选的 HID 通道已就绪              | 先验证 `0x02` 应答类型 `0x03/0x06`，再验证完整 `0x30` 输入；失败断开，不轮流试其他厂商命令                                     |

候选分类参考 [SDL_GetGamepadTypeFromVIDPID](https://github.com/libsdl-org/SDL/blob/main/src/joystick/SDL_joystick.c)，不照搬供 UI 使用的外观类型判断。即使名称是宽泛的 `Wireless Gamepad`，也必须通过有界协议验证；仅分类成功不会创建虚拟输出。

SDL 新增 Sony/Joy-Con 候选需收到完整输入，Xbox 候选需收到主输入报告后才启用虚拟输出；仅电量或 Guide 报告不足以通过。SDL 原始头文件及更新方式见 [设备分类](controller-config.md#sdl-设备分类)。

身份、协议和可用性是三个层次：名称／VID/PID 选候选，协议应答确认兼容，真实输入才能启用桥接。BLE 另走既有白名单、加密、PnP 身份、GATT 报告订阅流程，不使用 Classic 的名称／地址候选规则。USB 入口及初始化在本分支没有调整。

## Classic 身份缺失的 Switch 候选

这里与 Linux 的入口匹配需要区分：`hid-nintendo` 用总线类型及 VID/PID 设备表绑定驱动，随后由 `joycon_read_info()` 发送子命令 `0x02`，从应答读取控制器类型（例如 Pro `0x03`、Licensed Pro `0x06`）。类型不是广播或 SDP 中的通用身份，必须先建立 HID 通道并发送 Nintendo 命令才能取得。Valve `steam-devices` 中的 `Lic Pro Controller` 名称规则用于授予 hidraw 访问权限，不是内核协议匹配规则。本项目参考 SDL 的精确名称列表为零 VID/PID 设备筛选查询候选，再用应答和完整输入确认；这一步是本项目的兼容入口，并非 Linux 内核直接采用名称识别。

协议选择支持精确 Classic 地址／名称覆盖，具体 JSON 与优先级见[手柄配置](controller-config.md)。零 VID/PID 且名称精确为 `Lic Pro Controller`、`Nintendo Wireless Gamepad` 或 `Wireless Gamepad` 的设备作为 Switch 候选；已保存的验证类型仅用于回连提示，不改写 VID/PID。名称来自用户选择的发现结果，缺失时仅对自有已认证连接发起一次有界远端名称查询。

候选先经过蓝牙认证、加密及 HID 通道建立，再发送 Switch `0x02` 设备信息查询。收到有效应答且类型为 `0x03`／`0x06` 后执行已有初始化，完整 `0x30` 报告通过长度检查后才对外触发连接事件。错误类型、拒绝、查询超时及始终无完整输入均断开，不创建虚拟输出。查询有独立重试上限和 2.4 秒期限，整个连接仍受现有 setup 超时约束。不会对所有未知 HID 设备盲发 Switch 命令。

配对记录仍为原有 64 字节格式，保留区保存验证类型及标记，旧版本写入的零保留区正常读取；只有设备通过完整输入验证后才保存类型，回连重新验证。遗忘／清空配对同时删除此提示。`[bt-identify]` 日志记录候选来源、应答类型和失败原因；认证阶段不依赖此识别，现有认证策略、HCI 选择及 BLE 接入权限不变。

## Nintendo Classic 协议模块

`protocols/nintendo.c/.h` 管理一代 Switch 的子命令、输入、电量、震动编码和类型差异；`profiles.c` 保留注册、选择及名称规则。USB 专用握手与 Switch 2 USB 状态机仍在原有 USB 模块，未移植新 USB 功能。

常规已知 Nintendo profile 初始化先发送可选的 `0x02` 设备信息，再设置 `0x03` 报告模式、按类型选择 IMU／震动启用及玩家 LED。设备信息缺失不阻断原有已知身份路径；候选路径仍强制验证。已取得有效设备信息且类型有摇杆时，追加 `0x10` 读取工厂校准：左 `0x603d`、右 `0x6046`，各 9 字节。应答校验地址、长度、请求状态及范围；缺失或无效数据继续使用默认值。候选完成身份验证后，校准 `0x21` 应答仍进入元数据解析，但不能满足完整输入门槛或发布按键帧。Licensed Pro 不推测其 SPI 布局，不读取工厂校准。没有新增 flash 写入、配对擦除、复位或固件更新命令。

| 设备／类型                | 本轮处理                                                                        | 验证边界                                                       |
| ------------------------- | ------------------------------------------------------------------------------- | -------------------------------------------------------------- |
| Switch Pro、Joy-Con L/R   | 设备信息、可选工厂摇杆校准；保留独立半手柄方向                                  | 主机回归，不代表新增实机认证                                   |
| Licensed Pro `0x06`       | 默认校准，兼容初始化；可选功能没有应答不单独阻断输入                            | PowerA 认证仍需另行验证                                        |
| HORI `0f0d:00f6`          | 修正原表误标的 DS4/Onyx，选择 Switch；修正原始 X/Y 位交换；禁用无硬件马达的输出 | 依据 Linux 驱动和补丁说明，PS5 待测                            |
| PDP `0e6f:018c`           | 加入 Switch Classic 身份，名称采用 REALMz；BLE 仍关闭                           | 依据 Linux 设备表与 SDL 型号名，PS5 待测                       |
| NES 类型 `0x09/0x0a`      | 根据设备信息区别于同 ID 的 Joy-Con；无摇杆轴保持居中                            | 两个面键按 Linux 的 south/east 语义映射 Cross/Circle           |
| SNES `0x0b`               | 保留面键／十字键，缺失摇杆居中；不启用 IMU 或震动                               | 无实体测试                                                     |
| Mega Drive/Genesis `0x0d` | A/B/C→Square/Cross/Circle，X/Y/Z→L1/Triangle/R1，Mode→Create；缺失摇杆居中      | 查询类型可纠正其复用的 SNES 身份                               |
| N64 `0x0c`                | 单摇杆、Z/ZR、独立 C 键；C 键归一为右摇杆四向，A/B→Cross/Circle                 | C 键到 PS 轴的映射是本项目策略；本轮保留原表关闭震动的能力限制 |

原始 HID 位与控制器类型依据 [Linux hid-nintendo.c](https://github.com/torvalds/linux/blob/master/drivers/hid/hid-nintendo.c)。未知／错误的电量编码不再输出超过 100% 的电量。所有设备名、类型和规则仅表示协议身份，不是制造商认证。

## 生命周期与安全边界

HCI使用旧项目的受限访问实现，不reset或detach系统驱动，不提高线程优先级。第一HCI功能与系统功能是否完全隔离尚未证明。仅在手动启动或自动启动门槛满足后打开；首次实机仍须确认原装DualSense共存正常，不能把模拟测试当成共存验证。

停止/休眠先尝试释放/删除自有虚拟输出，同时保证即使删除失败也关闭共享蓝牙传输；保留句柄继续清理。初始化等待期间持续观察电源。配对任务有期限，连接、通道、报文重组均有上限。不开放自动切换到其他HCI接口。

## 存储与日志

本应用独立 /data/unicontroller/bonds.db，格式继承迁移的host栈；临时文件权限0600、fsync后原子替换。与settings.json隔离，不读取/清理PS5系统配对记录。原项目的配对文件不会自动迁移。

保留驱动匹配、初始化、收包/解析计数、状态、错误原因等元信息；不记录配对密钥或原始HCI/ACL载荷。移植栈的兼容日志统一归Info，受后台记录阈值控制。结构化core日志与平台runtime.log仍可从网页导出。

### 配对诊断

默认 Info 记录认证／加密结果；等待期间每 5 秒记录当前阶段，每条连接最多 4 条。Classic 连接释放时输出一条 `[bt-security] summary`，包含认证／加密状态、耗时，以及是否收到 PIN、旧密钥请求、新密钥通知、IO 能力请求／响应、用户确认和 SSP 完成事件。字段 `0` 表示本应用未观察到该事件，不代表设备一定未发送。

排查配对超时时先把后台日志级别设为 Debug，再忘记本应用中的设备并重新配对。Debug 另记录连接类型和初始加密状态、双方 IO 能力及认证要求、回复命令 `queued`、命令完成／状态和新密钥类型。`queued=1` 仅表示发送接口接受，不表示控制器执行成功；需结合 command status、认证和加密结果。若收到当前未处理的 Passkey／OOB 请求，会按每种请求每连接一次记录 Warn，汇总中的 `unsupported` 非零便于定位。不会记录 PIN、链路密钥或数字确认值；未改变 PIN、安全参数和重试策略。

## BLE 接入策略

BLE 默认拒绝，只有内置设备记录明确 `ble: true` 或用户覆盖规则明确开放的身份可以接入。当前内置仅开放 Xbox `045e:0b13`（HOGP）。设备名称、Classic profile、USB ID 或 HID 布局本身不授予 BLE 权限。一代 Switch 协议和已知 Switch 2 身份继续拒绝，即使用户配置 `ble: true` 也不绕过。

用户覆盖文件 `/data/unicontroller/controllers.json` 的设备规则可使用 `match: {transport: "ble", vid: "1234", pid: "5678"}` 和 `ble: true`。`ble: false` 可关闭内置已开放身份；字段仅允许用于 BLE 规则。通用 HID 仍可用于显式开放的未知设备。

首次需要连接读取 PnP ID。当前栈仍先完成加密握手再查询 GATT，未改为配对前查询；身份未通过前不保存新密钥或发布手柄就绪事件。取得明确身份但白名单拒绝时，发现列表显示“不支持”并禁止再次配对；已有被拒绝的缓存身份在扫描时可直接显示，不发起连接。缺少/读取失败的身份仍作为失败处理，不误标为已确认不支持。已有配对在发起回连前也检查权限，记录保留供用户查看与删除，不自动删除历史数据。拒绝身份暂缓再次尝试 60 秒。输入通知订阅失败或没有可订阅输入报告时退出初始化。

## Switch 2 BLE：仅识别，不支持配对

根据 Nintendo Manufacturer Data（公司 ID `0553`、VID `057e`、完整已知广播结构）识别 Pro `2069`、Joy-Con L/R `2067/2066`。名字相似不会触发识别。格式依据 [Switch 2 蓝牙协议研究](https://github.com/ndeadly/switch2_controller_research/blob/master/bluetooth_interface.md)。

识别结果在发现列表显示型号、状态 `unsupported` 和原因 `switch2_ble_not_supported`，中英文页面显示“暂不支持”，禁用配对按钮。后端和内部点选入口同样拒绝；不会发起 LE Create Connection、SMP 或 GATT，不创建虚拟输出，不保存配对。旧的 Switch 2 配对身份也不能绕过 BLE 拒绝策略。

试验性的私有 GATT 会话和报文解析代码已删除，没有保留草稿模块。若后续重新实现，应使用独立 Switch 2 协议，不复用一代 Switch。USB 实现不受此调整影响。`make test-bluetooth` 的虚拟广播测试覆盖三种型号，并断言主动调用配对也不产生连接命令。

## 可选自动启动

设置页保留 `bluetooth_auto_start` 布尔开关（默认 false），新增 `bluetooth_auto_trigger`：`login`（默认，登录进入桌面）或 `resume`（实验，休眠恢复）。旧配置没有 trigger 时按 login 读取。两种策略均等待连续稳定 5 秒、所有输入源停止和旧虚拟输出清理完成；每轮仅尝试一次，失败不自动重试，不自动开启配对，不实现第三方手柄唤醒。

### 登录进入桌面（推荐）

payload 启动、保存设置或休眠清理后，等待系统工作，再观察最多 120 秒。先排空日志历史，等待新的 SceShellUI 桌面焦点事件（`Render.NPXS40002`），确认前台用户和已保存的绑定账号已登录，连续稳定 5 秒后启动蓝牙。离开桌面或条件失效会取消计时。

桌面焦点来自现有日志流，不是官方物理手柄登录回调，不能证明登录来自哪只手柄。复用虚拟设备识别的日志读取器，读取有界；识别和观察不会同时争抢 `/dev/klog`。日志不可用、断开、观察超时均保持关闭，允许手动启动。在桌面已稳定时加载 payload 不会拿旧事件补触发，需要新的桌面焦点事件或手动启动。

### 休眠恢复（实验）

只在运行中检测到休眠/恢复周期后触发，加载 payload 或保存设置不触发。沿用平台的保守休眠检测：明确休眠电源状态或超过 2 秒的事件循环中断都会请求清理，长中断也可能触发该策略。系统恢复工作并连续稳定 5 秒后启动蓝牙，不要求有已登录用户，也不依赖桌面日志。恢复后最多等待 120 秒；被其他输入源持续占用时不抢占。

首台收到新有效输入的实体手柄创建未由应用绑定的虚拟设备，允许未登录时注入 PS/Home、方向和确认等按键。该路径跳过 `sceMbusBindDeviceWithUserId`，保留同一虚拟设备继续注入，让系统用户选择流程决定账号归属。保存的账号不用于这个模式，网页主动账号分配禁用。仅允许一只实验输入源，核心与平台都阻止它和其他应用虚拟输出混用。

此路径目的是实测“第三方手柄操作用户选择并进入游戏”，不保证系统会完成绑定。尚无可靠的设备归属查询接口，页面单独标注输出是否已启用，以及“系统绑定未确认”；不把已登录用户或前台账号作为该设备归属。日志记录虚拟设备创建、首次输入/PS键注入结果和用户列表变化；输入提交成功也不能证明游戏已经接收。

账号登录/退出不会触发应用重绑或重建设备，便于测试系统自身的用户切换。原有输入超时释放、断线清理、停止及休眠删除仍生效。提前访问 HCI 和未绑定虚拟设备是否影响原装手柄恢复尚待实机验证，因此保留实验标记和默认关闭。测试步骤见[实机清单](test-checklist.md)。

### 账号与取消规则

保存上次**手动成功启动蓝牙**的账号到 settings.json 的 `bluetooth_auto_user`；默认 0 表示无记录。前台用户与绑定账号可以不同，不把第三方手柄自动改绑主手柄账号。设备卡片分配用于当前会话，额外实体手柄仍单独分配，不宣称已持久化每台手柄的账号。

手动启动/停止取消本轮自动任务。休眠清理取消旧计时与日志状态，恢复后按所选策略重新等待。USB 现在有独立自动启动开关，共用启动时机；恢复实验只允许选择一种连接，USB 可在未登录时注册虚拟输出。详见 [配置与日志](settings-storage.md#usb-与蓝牙自动启动)。不自动设置系统辅助控制器模式。

源码基线核对、修正与尚未消除的差异见[蓝牙基线对比](bluetooth-baseline-review.md)。正常路径仍主动绑定账号；不要将休眠实验路径解释为所有启动方式。

## 扫描与显式配对 API

- `POST /api/v1/bluetooth/scan`，`{"seconds":60}`：开始发现，不连接新设备。允许1–120秒。
- `POST /api/v1/bluetooth/scan/stop`：停止发现，不停用蓝牙、不删除配对、不取消已经选中的连接。
- `GET /api/v1/bluetooth`：包含 `scan_id`、`scan_seconds` 和 `discovered`；每个结果包含 `id`、名称、地址、传输、LE地址类型、RSSI、状态和错误原因。首次发现不一定有可靠的VID/PID，名称缺失时仍通过MAC与传输区分。
- `POST /api/v1/bluetooth/pair`，`{"discovery_id":7}`：只接受本轮发现过且未过期的结果；不能直接传任意MAC发起连接，也不再接受原来的 `seconds` 请求体。

所有写接口继续要求会话令牌与同源校验。前端与payload需要一起更新。发现列表仅在内存保存，最多16条；同地址的Classic／BLE、不同LE地址类型分别标识，不按MAC前缀合并。结果在最后一次看到后的120秒过期，重扫／关闭服务立即作废旧ID。配对任务串行；额外设备仍受四个实体输出等原有限制。只展示广播／EIR中的名称，不为显示名称额外建立临时连接。

已有配对设备的正常回连不需要再次点击，不属于新设备自动配对。标准 HOGP 设备在用户点选后读取身份，继续执行白名单及一代 Switch BLE 拒绝策略。Switch 2 通过厂商广播仅显示型号和不支持状态，不发起配对；未知身份不能仅凭广播判定受支持。

扫描期间控制器忙时Inquiry重试有1秒间隔，不刷屏忙循环。Classic“连接已存在”不会遍历断开未知句柄；BLE Create被拒绝为0x0c时不取消系统可能正在执行的连接，仅做自身有界退避并报告失败。共享HCI的共存风险仍需实机验证。

丢包模拟的语义也区分“工作”与“明确失败”：Classic压力样本仍全部连接；BLE在10%丢包下模拟最多五次显式用户重试，当前29/30工作，1/30可见失败并保持等待用户操作，没有退回广告触发的自动重配对。该人工丢包结果不是实机兼容率。

## 系统原生手柄过滤

DualSense（054c:0ce6）和 DualSense Edge（054c:0df2）交给系统蓝牙处理，不通过本应用桥接。Classic 扩展扫描结果带有 USB 来源 Device ID 时直接过滤；后续结果补充身份时移除已有发现项。普通扫描没有可靠身份时仍可能暂时显示，不能仅凭 Wireless Controller 名称判断。取得 SDP 身份后会在 HID 初始化和虚拟设备注册前停止本应用拥有的连接；缓存为这两种身份的旧配对记录也不参与本应用回连。BLE 身份检查不可通过自定义白名单绕过。不会删除系统配对或操作系统拥有的连接。

DualShock 4 保留手动桥接入口：系统原生支持其用于兼容 PS4 游戏，桥接用于 PS5 游戏仍需实机验证。设备表及协议解析器保留，不将蓝牙过滤扩展到 USB 或所有 Sony 设备。

## 调试日志

Debug 级别补充 HCI 硬件身份、接口布局及实际选择，认证/加密命令状态、PIN/Link Key 请求、IO capability、Simple Pairing Complete、LE 扫描拒绝状态和断开前链路阶段。日志不输出密钥、PIN 或确认数字；接口选择和配对策略不变。

设备详情“重新选择使用者”的接口、并发限制和验证要求见 [USB 文档](usb.md#重新选择使用者)，蓝牙使用相同清理与系统选择规则，不重新配对。
