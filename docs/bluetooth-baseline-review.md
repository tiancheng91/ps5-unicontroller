# 蓝牙基线对比与验证边界

基线为本地 `ps5-wireless-pads` 提交 `5a3c72e`，比较目标为 UniController `7ea118c` 加当前工作区修改。旧项目具有用户实机验证记录，本文的源码一致性与主机测试不能替代新 payload 实机验收。对比按统一 C 格式化后进行，避免把目录、格式和日志文案变化误认为协议变化。

## 核对结果

| 环节                     | 对比结果与处理                                                                                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| HCI USB                  | 节点、端点选择、40 个事件读取与20个ACL读取相同；主要差异是诊断载荷脱敏。没有证据将这些旧参数认定为此次回归原因；共享 HCI 的共存风险仍需实机验证。                                              |
| USB描述符、事件流重组    | `usb_desc.c`、`evstream.c` 按统一格式化后相同。这里指蓝牙适配器的 USB 通道，不代表有线手柄驱动相同。                                                                                           |
| Classic 扫描／配对／回连 | 沿用旧 host 状态机、认证、加密、SDP、控制／中断通道。新增配对文件权限和同步写入，协议选择改为按传输查询配置。                                                                                  |
| Switch 专用协议          | `switch_parse`、`switch_init`、`switch_output`、`switch_rumble_motor` 按统一格式化后相同。本次不重新设计这些函数。                                                                             |
| BLE                      | 保留当前明确的白名单策略和 Switch BLE 拒绝策略，不恢复旧版同一实体出现 Classic／BLE 两个入口的行为。不能从 VID/PID 或相似地址认定 BLE 可用。                                                   |
| 虚拟设备参数与输入       | 沿用大小32、user参数1、DualSense类型3、120字节输入ABI、低32位设备句柄与单调微秒时间戳。新项目另有统一映射和租约层。                                                                            |
| 设备识别                 | 旧版允许缺少电量能力字段；新项目原来强制完整字段，现已修正。明确声明有电池的真实手柄仍拒绝作为候选，保留串行创建、多个候选拒绝和已有设备排除。                                                 |
| 权限提示                 | 旧版不将 `scePadSetProcessPrivilege` 返回非零当作初始化失败；现与此保持一致，实际注册、绑定、输入结果仍检查。                                                                                  |
| 日志源                   | TCP日志服务在 AddDevice 前关闭时，允许回退 `/dev/klog`；不在创建中途切换来源。EINTR在有界读取循环内重试。                                                                                      |
| 账号绑定                 | 旧版确实调用 `sceMbusBindDeviceWithUserId`，不是完全由系统自动分配。正常模式继续主动绑定；默认推荐账号恢复为已登录初始用户、前台用户、首个已登录用户的顺序。网页明确选择其他账号仍可覆盖默认。 |

## 有意保留的差异

旧项目在蓝牙 HID 通道就绪时注册虚拟手柄；当前项目等待首个有效解析输入后注册，避免无输入的设备占用虚拟输出。当前额外实体手柄需独立账号和显式分配，不假定所有设备属于一个用户；账号冲突保护没有移除。

休眠恢复时不主动绑定的路径仍是默认关闭的实验选项，不代表正常模式。正常模式的账号推荐策略与 UI/API 选择是应用策略，不能把页面账号字段称为已查询到的系统最终归属。

创建失败自动循环不属于基线正常流程：现已停止整个蓝牙服务、释放共享 HCI，必要的虚拟输出清理继续重试；必须手动启动才能再试，避免每一帧输入再次注册。

旧项目有多次 HCI 启动与原始凭据重试；当前仍只在明确手动启动时做一次有界尝试。本轮日志显示能扫描和配对，未以启动重试扩大改动。未将旧的诊断账号文件路径和产品存储目录带入新项目。

## 验证与下一次实机

主机测试包含 Switch Classic 配对、初始化到完整输入、异常ACL、回连、BLE身份拒绝；平台模拟测试包含设备识别、缺失电量字段、真实手柄排除、多候选拒绝、账号选择、主动绑定与独立输出。测试环境的假 MBus 返回值不证明 PS5 接口成功。

先保持自动启动关闭，使用一只已验证的 Classic Switch 模式手柄：

1. 原装手柄登录并确认系统菜单正常；先不同时启用 USB 或手机测试输出。
2. 启用蓝牙；已有配对先测试回连，只有未配对设备才点击“新增蓝牙设备（60秒）”。
3. 观察输入帧数和电量，再检查运行日志中的 `add`、`bind_user` 和 `input ... rc`。输入帧增长只证明蓝牙输入已解析，不证明虚拟输出成功。
4. 虚拟创建失败应停止蓝牙，不能再出现连续 session 创建。出现原装手柄失效立即结束本轮实验并导出诊断。
5. UI 操作正常后，用所绑定账号启动游戏；多人场景再使用独立账号验证。

完整诊断由管理页“导出”提供，包含核心事件、蓝牙／USB／系统状态与底层日志尾部。单独核心 JSON 环形日志不能定位 SDK 返回值或 USB 枚举问题。Actions 交叉构建与实机仍是交付前检查项，不把主机通过表述为已修复实机故障。

## 显式配对更新

新设备发现与连接现已分离：扫描缓存16个结果，用户选中ID后才启动原认证／协议流程。已配对设备继续自动回连。另移除了Classic未知句柄遍历清理及BLE对外部待连接任务的取消，优先保护系统手柄；这些是有意偏离旧基线的安全修正。接口、结果有效期和验证数据见 bluetooth.md。
