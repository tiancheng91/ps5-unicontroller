# 实机测试清单：自动启动、系统用户选择与面键布局

状态：**待实机验证**。主机测试和 Actions 成功只说明编译及模拟回归通过。逐项反馈“通过 / 失败 / 未测”，不要把网页输入变化当作游戏输入成功。

## 准备

- 从本次提交的成功 Actions 下载 `UniController-PS5`，记录 `build-info.txt` 的 commit/run；停止旧 payload 后加载新 ELF。
- 记录 PS5 固件、手柄型号/固件/模式、Classic/BLE/USB；本轮先只连接一只已知可用的第三方手柄。
- 保留原装手柄备用。网页可以访问；建议后台日志设为 Debug。测试前停止其他输入源及手机测试手柄。
- 为登录实验准备好蓝牙配对记录；先用常规模式配对成功，再测试恢复。不要在每轮测试前清空 bonds。
- 未测试项保持“未测”；任何一步导致原装手柄也失效，应停止本轮、保存诊断，勿继续反复配对掩盖故障。

## 1. 基线：关闭自动启动

- [ ] 自动启动关闭，原装手柄单独操作正常。
- [ ] 手动启动蓝牙、连接第三方手柄，网页有输入和电量（若设备上报）。
- [ ] 常规模式选择独立已登录账号，系统菜单和该用户的原生 PS5 游戏都可操作。
- [ ] 手柄断开/回连不需要重新配对；两只手柄没有互相抢占账号。
- [ ] 休眠恢复后蓝牙保持关闭，原装手柄可正常登录与操作。

## 2. 面键布局：两组都切换

先使用恒等自定义映射；每次修改前停止输入源。按实体手柄印字分别记录结果。

- [ ] 关闭布局切换：Switch B→Cross、A→Circle、Y→Square、X→Triangle。
- [ ] 开启布局切换：Switch A→Cross、B→Circle、X→Square、Y→Triangle。
- [ ] 同时按 A+B、X+Y 能同时保留两个按键；方向、PS/Home、肩键不变化。
- [ ] 设置保存后重新加载 payload 仍保留；此设置影响所有本应用输出，不仅 Switch。
- [ ] 游戏中的确认/取消和另外两枚面键也符合以上变化。

旧配置字段仍叫 `swap_ab`，开启后现在同时交换 A/B 和 X/Y；此前仅交换 A/B 的行为已修正。

## 3. 登录进入桌面后启动（推荐路径）

- [ ] 常规模式手动成功启动一次蓝牙，记录选择的账号；随后停止蓝牙。
- [ ] 设置开启自动启动，选择“登录进入桌面后”。
- [ ] 进入休眠再恢复：在用户选择界面尚未确认时不应启动蓝牙。
- [ ] 用原装手柄完成登录并进入桌面；已保存账号也需已登录。稳定等待至少 5 秒后启动蓝牙，第三方手柄回连。
- [ ] 倒计时期间离开桌面，启动被推迟；回来后重新等待 5 秒。
- [ ] 手动停止蓝牙后保持关闭，不立即自动重开。

日志参考：`history drained` → `fresh desktop focus=1` → `waiting 5000ms` → `desktop delay complete` → `start result=0`。观察窗为 120 秒，未收到新桌面事件不会用旧日志补触发。

## 4. 休眠恢复后启动：不用原装手柄完成用户选择（重点）

- [ ] 设置开启自动启动，选择“休眠恢复后（实验）”；保存不会立即启动。
- [ ] 进入休眠，关闭原装手柄。使用**主机电源按钮**恢复，暂不使用原装手柄确认用户。不要把第三方手柄唤醒作为测试目标。
- [ ] 恢复工作状态后约 5 秒或更晚蓝牙启动；已配对第三方手柄回连，不重新配对。
- [ ] 网页设备卡片有输入帧，随后显示虚拟输出启用、系统绑定未确认。
- [ ] 第三方手柄按 Home/PS；如果首次按键发生在虚拟设备初始化前，等输出就绪、松开后再按一次。
- [ ] 只用第三方手柄方向键及确认键操作 PS5 用户选择；记录出现的界面、选择了哪个用户。
- [ ] 进入桌面，打开一个原生 PS5 游戏；验证方向、四个面键、摇杆、肩键、PS菜单与返回游戏。
- [ ] 登录前后没有被应用删除并重新创建虚拟手柄、没有再次主动改绑账号。
- [ ] 停止蓝牙后原装手柄可以恢复正常使用；再次休眠后重复至少两轮。

实验模式忽略保存的账号，不调用 `sceMbusBindDeviceWithUserId`；仅一只实体输入源向系统注入，网页账号分配不可用，不与其他应用虚拟输出混用。

日志参考：`resume delay complete` → `started_system_choice_experiment` → `[system-choice] ... registered without application binding` → `input accepted ... ps=1`。`signed_in=... foreground=...` 只是用户状态观察，**不是设备绑定成功证据**。要以系统用户选择和游戏操作结果为准。

分别记录这四项：**回连成功 / 登录界面输入 / 完成用户选择 / 游戏输入**。即便前三项成功，最后一项也可能失败。

## 5. 清理与故障恢复

- [ ] 按住方向时断开实体手柄，系统不会持续移动。
- [ ] 网页停止蓝牙后，虚拟输出被删除；新连接不会继承上一轮按住状态。
- [ ] 自动启动失败后不会不断重试；可以手动停止/重新启动或关闭自动启动。
- [ ] 原装手柄异常时，网页仍能停止蓝牙或程序。若无法恢复，保存日志后使用主机正常电源操作恢复。
- [ ] 普通休眠与停止不删除配对记录；“忘记设备”才删除本应用对应记录。

## 6. 可选扩展

完成以上基线后再测，避免多个变量同时变化。

- [ ] 常规模式两个独立账号、两个实体手柄的游戏输入及震动分别正确。
- [ ] USB Switch/XInput的按键、震动、长按及拔插；USB休眠后不自动启动。
- [ ] 图标打开配置页；局域网 7456/7457 与实际监听端口一致。
