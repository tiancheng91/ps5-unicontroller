# Native HTTP runtime

Pure C11, single event-loop owner, no external libraries. `uc_runtime_run(bind,port,settings_path)` follows backend initialization. Core polling and 500ms deadman checks run every iteration even with slow clients. Eight sockets, 4KiB headers, 8KiB request bodies, three-second deadlines, one request per connection, bounded JSON depth/tokens, and five-millisecond loop pacing bound resource use. No Bluetooth or WebSocket implementation is included. The mobile controller uses HTTP input and heartbeat posts.

GET `/api/v1/session` returns a fresh process-local 256-bit token. Mutations require `X-UC-Token` and exact `Origin` matching the accepted socket's local literal IPv4 address and port. Host must match that authority too; use `http://IP:PORT`, not a DNS hostname. No CORS is emitted. Session bootstrap relies on browser same-origin isolation, and plain HTTP has no confidentiality; run on a trusted LAN. Tokens are neither logged nor persisted.

GET `/api/v1/system`, `/users`, `/settings`, `/logs?level=info` and `/test-controller` are under `/api/v1`. Logs return plain-text complete lines from the active runtime log (last 32 KiB, filtered by severity); `/diagnostics` is the unfiltered compatibility alias. Structured core events are available at `/core/events?level=trace` for diagnostic exports. POST `/test-controller` accepts `{user_id}`; 202 `{pending:true}` requires explicit retry while the platform identifies the new output. DELETE cancels pending creation and releases/deletes the owned output. POST `/test-controller/input` accepts session ID, monotonic sequence, button mask, four signed 16-bit axes and two unsigned 16-bit triggers. Neutral input releases buttons; lost clients are released by the independent core timeout.

Settings POST requires the complete flat schema with schema_version=1, recording_level, page_level, rumble, swap_ab, and 32 mapping entries in 0..31. Unknown/duplicate keys and invalid numbers fail. All settings may be saved live. Button-map and test-layout changes apply to the next full input report without recreating sessions or changing account assignment. Core validation runs before persistence. Saving startup preferences while connected affects the next suspend cycle and does not restart any inputs. A mode-0600 temporary document is fully written and fsynced before rename; only then is memory replaced and core recording/mapping applied. A corrupt stored file blocks startup. Directory fsync, concurrent process writers and symlink-hardening of a hostile settings directory are outside this single-process trusted-directory MVP. The global rumble switch gates physical feedback; per-device options are stored separately. Pairing secrets are outside this model.

Recording level limits retained lifecycle logs; page level/query filters existing entries only. Settings persistence errors emit fixed redacted stderr codes. Core provides bounded entries and dropped count; arbitrary input bodies, headers, user names and credentials are never copied into logs.

HTML is embedded through `uc_index_html`, `uc_controller_html` and `uc_settings_html`, served at `/`, `/controller`, `/settings`. Without assets, weak minimal fallback pages are served. Transport responses use no-store, nosniff, no-referrer and frame-ancestor protection.

Host checks from repository root:

```
cc -std=c11 -Wall -Wextra -Werror src/web/runtime.c tests/web/host_main.c tests/web/host_backend.c src/core/uc_core.c -o /tmp/uc-c-http-host
cc -std=c11 -Wall -Wextra tests/web/test_json.c -o /tmp/uc-c-json-test
/tmp/uc-c-json-test
python3 tests/web/test_runtime.py /tmp/uc-c-http-host
```

The HTTP integration check requires local socket permission. The host backend records lifecycle in memory and does not validate PS5 hardware behavior.

固定监听7456；启动时 socket、绑定或监听失败立即退出，不再回退7457。休眠不主动关闭监听；SIGCONT或事件循环长间隔后检查并重新确认监听。运行期失败记录阶段和errno，每秒最多重建一次，连续10次恢复仍未成功接受请求则退出。恢复网络不会启动蓝牙或USB。

## Bluetooth HID diagnostics

GET `/api/v1/bluetooth/diagnostics` returns a read-only snapshot of connected devices.
Generic HID initialization caches up to 1024 descriptor bytes per link, released
on disconnect. After updating to a build with diagnostics, reconnect the device
to populate the cache. Dedicated profiles may not request a descriptor and return
`descriptor_available: false`.

Available descriptors include `descriptor_hex`, source (`sdp_hid_descriptor` or
`gatt_report_map`), length/truncation, and an Output/Feature report inventory with
report IDs, payload bit/byte lengths, report-ID prefix presence, and usage pages.
`pid_usage` (page 0x0F) and `vendor_usage` (0xFF00+) are protocol hints, not proof
of working vibration. Invalid or incomplete inventories must be interpreted with
their validity/truncation flags and the raw descriptor. No report values, feature
reads, radio requests, or vibration probes are generated by this endpoint.
The normal web diagnostic export includes this snapshot.

Device preferences use authenticated POST `/api/v1/device-settings` with `key`, `session_id`, `rumble`, and `swap_ab`. The key and session must match a connected physical device; stale identities return409. Preferences persist in sibling `device-settings.json` before being applied to managers, without changing output registration or account assignment. Device status exposes the preferences, a stable configuration key, known-device classification and separate output capability. Global `swap_ab` now applies only to the test controller; physical adapters swap per device before core custom mapping.
